# .letterstomy Archive Format

## Overview

The `.letterstomy` file is the portable encrypted archive format used for
backups and recovery. It is designed to remain usable long after the app
or company that created it has disappeared.

A `.letterstomy` file can be:

- Saved to a local filesystem
- Stored in iCloud Drive through the app's ubiquity container
- Exported to Google Drive, Synology NAS, Nextcloud, S3, or WebDAV
  (through optional providers)
- Sent to a recovery contact

## File structure

A `.letterstomy` file is a single binary blob containing:

```
[ AES-256-GCM combined ciphertext ]
```

There is no unencrypted header or footer. The first bytes are the AES-GCM
nonce (12 bytes), followed by the ciphertext, followed by the 16-byte
authentication tag. This is the standard `AES.GCM.SealedBox.combined`
representation from Apple's CryptoKit.

## Encryption

| Parameter | Value |
|-----------|-------|
| Algorithm | AES-256-GCM |
| Key derivation | SHA-256(passphrase UTF-8 bytes) |
| Nonce | 96-bit random (generated per archive) |
| Authentication | 128-bit GCM tag |

The passphrase is never stored in the archive. Losing the passphrase
means the archive cannot be recovered. Recovery contacts may hold
fragments of the passphrase or recovery key to assist.

## UUID stability

Every record carries a stable UUID (`id` field). These UUIDs are:

- Generated by `awakeFromInsert()` in Core Data
- Preserved through CloudKit synchronization
- Never regenerated during restore
- Used for duplicate detection during import

## Restore behavior

When a `.letterstomy` file is imported:

1. The file is decrypted with the provided passphrase
2. The archive is previewed (counts of letters, attachments, recipients)
3. On confirmation, each record is inserted into the private Core Data store
4. Duplicate detection skips records whose `id` already exists
5. Attachments are re-imported with their original data and identifiers
6. Unlock rules, sealed status, and collaboration metadata are preserved

## Version compatibility

| Version | Changes |
|---------|---------|
| 1 | Initial format. All current payload types. |

Future versions must:

- Increment `formatVersion`
- Never remove fields that older archives may contain
- Add new optional fields at the end of each payload struct
- Document the version change in this file
- Keep the encryption envelope unchanged unless a security vulnerability
  is discovered

## Security considerations

- The archive is encrypted before it leaves the device
- The passphrase is never transmitted or stored by the app
- Attachment data is included inline (not as external references)
- CloudKit tokens and Apple credentials are never included
- Recovery contacts receive encrypted archives, not plaintext
- The format uses standard AES-256-GCM with no proprietary extensions

## Recovery without the app

A `.letterstomy` file can be decrypted outside the LettersToMy application
using any tool that supports AES-256-GCM with the SHA-256-derived key:

```python
# Example: decrypt with Python + cryptography library
import json
from cryptography.hazmat.primitives.ciphers.aead import AESGCM
import hashlib

with open('archive.letterstomy', 'rb') as f:
    combined = f.read()

nonce = combined[:12]
ciphertext = combined[12:]

key = hashlib.sha256(passphrase.encode('utf-8')).digest()
aesgcm = AESGCM(key)
plaintext = aesgcm.decrypt(nonce, ciphertext, None)
payload = json.loads(plaintext)
print(f"Letters: {len(payload['letters'])}")
print(f"Recipients: {len(payload['children'])}")
```
